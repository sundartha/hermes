## Ursache (aus dem Code)
`src/elevenlabs/vorspann-ablauf.js:146` (`auflegenFuer`): das Gesprächsergebnis wird beim Ende nur abgeholt und gespeichert (`hangUpForCall` → `awaitAndPersistInboundElResult`), wenn `aufzeichnung.bridgedAt` gesetzt ist. Kommt das Ende vor `bridgedAt`, wird nur aufgelegt; der Anruf wird `completed` ohne Transkriptzeilen. Der Test wartet auf die Gesprächs-ID (`konversation`) und beendet dann sofort. Mit PR 5491 steht die ID vor der Init-Antwort in der DB, also vor `bridgedAt`; unter CI-Last wird der Abstand groß → rot. Auf master kam die ID erst nahe `bridgedAt` → fast nie rot. Echter Produktfehler (Transkriptverlust bei Ende vor Brücke), keine Uhr-/Wartezeit-Frage (Regel uhr-als-wert nicht betroffen). Lokal auf dem Server nicht nachstellbar (kein Postgres); Bau-Agent: 60/60 grün ohne Verzögerung, mit 800 ms Verzögerung rot.
