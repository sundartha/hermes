## Konfidenzmass: existiert nicht im Code

`grep -rn "confidence"` (case-insensitive) ueber `src/` liefert AUSSER den o.g.
Docstring-Fundstellen zu `parseSpeechResult` KEINEN Treffer, der ein Confidence-Feld
tatsaechlich ausliest. Die Parser-Funktionen:

```
// src/telephony/adapters/twilio/webhook-events.js:9
export function parseSpeechResult(body) {
  return (body.SpeechResult || "").trim();
}

// src/telephony/adapters/telnyx/webhook-events.js:16
export function parseSpeechResult(body) {
  return (body.Transcript || body.SpeechResult || "").trim();
}
```

Beide extrahieren NUR den Text. Twilio liefert im selben Webhook-Body zusaetzlich
`Confidence` (Twilio-Doku, 0.0-1.0 Score pro SpeechResult), Telnyx analog ueber sein
Transcription-Event. Dieser Wert wird nirgends gelesen, nirgends geloggt, nirgends als
Gate benutzt ("wiederhol das bitte" bei niedriger Konfidenz existiert nicht). Ein
Nonsens-Transcript mit Confidence 0.2 wird identisch behandelt wie ein sauberes mit 0.95.

NICHT geprueft: ob Telnyx' `deepgram/nova-3`- bzw. `deepgram/flux`-Webhook ueberhaupt
ein Confidence-Feld im Payload mitschickt (Telnyx-Doku nicht eingesehen, nur Code).
Falls nicht, waere das Nachruesten eines Gates ein Provider-seitiges Datenproblem, kein
reiner Code-Fix.
